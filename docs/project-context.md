# Project context: `.ag/`

`agnostic` keeps everything an agent should know about a repo in one committed folder, and generates each agent's native config from it.

```
.ag/
  instructions.md     # the one file you maintain - conventions, architecture, do/don't
  preferences.yaml    # how the recommender should weigh quality, cost, speed
  decisions.md        # architecture decisions agents should respect
  tasks/              # one markdown file per task: spec, acceptance, status, handoff notes
  mcp.yaml            # optional: the MCP servers every agent here gets - see docs/mcp.md
  agnostic.yaml       # test and lint commands, default profile
```

## Creating `.ag/`

`agn init` creates the folder in a repo you have already registered (`agn add .`). It seeds `instructions.md` from the repo's existing `CLAUDE.md` or `AGENTS.md`, byte for byte, and leaves the original where it is; if both are present and they differ it stops and asks for `--from CLAUDE.md` or `--from AGENTS.md`. With neither, it writes a short template. `preferences.yaml` is written out with the default rules, `decisions.md` is empty, and `tasks/` is created. A file that is already there is kept; `--force` rewrites `agnostic.yaml` only. Init writes nothing at the repo root: the first `agn sync` does that.

## Generated files

`agn sync` writes two files at the repo root from `instructions.md`:

- `AGENTS.md` - the generated header, a blank line, then `instructions.md` verbatim. Codex, OpenCode and Pi read it.
- `CLAUDE.md` - the generated header and one line, `@AGENTS.md`, which Claude Code imports. The instructions exist in one copy.

From `mcp.yaml`, it writes each agent's own MCP configuration ([MCP](mcp.md)):

- `.mcp.json` - Claude Code's servers, merged by entry name; no header.
- `opencode.json` - OpenCode's servers, merged by entry name; no header.

Codex's servers go in a per-repo block of `~/.codex/config.toml`, which is outside the repo and is not committed.

The two instruction files start with the same first line:

```
<!-- generated by agn sync from .ag/instructions.md; edit that file, not this one -->
```

Commit them. A teammate without agn, a fresh clone and every worktree agn creates then carry the same instructions without running anything. Edit `instructions.md`, not the generated files. Settings a specific agent needs that don't translate (Claude Code hooks, Codex sandbox flags) stay in that agent's own config; `agn sync` never touches them.

`agn sync --dry-run` prints one line per file and the full text it would write, and changes nothing.

## When agn refuses to overwrite

That header is how agn knows a file is its own. A file without it is overwritten only when it already holds what sync would write - the state `agn init` leaves behind. Anything else is a file you wrote, so sync stops, names it, and writes nothing:

```
CLAUDE.md was written by hand and agn will not overwrite that
```

Merge what you want to keep into `.ag/instructions.md`, then run `agn sync --force`. There is no backup: git holds the old text.

The header means agn owns the whole file, so an edit made *below* an intact header is overwritten on the next sync without a conflict. Put the text in `.ag/instructions.md` instead.

## Sync while a task runs

`agn run` and `agn resume` sync the directory the agent is about to work in, from that directory's own committed `.ag/instructions.md`. A worktree cut from an older commit still starts with the current text. A repo without `.ag/` syncs nothing, and a file that would be a conflict leaves the task running on the file that is there, with one line in `~/.agnostic/logs/agnd.log`.

## `agnostic.yaml`

Four keys change what `agn run` does.

- `test_command` runs twice per task: in the new worktree after `setup_command` and before the agent starts, and again when the task ends. `agn outcomes` reports both results. The first run is what `agn run` waits for; pass `--skip-tests` to start the agent at once and record no baseline. A task that branches from a commit agn has already tested on this repo reuses that result and starts without waiting. Output goes to `~/.agnostic/logs/tasks/<task>.log`, and a command that takes more than ten minutes is abandoned and recorded as not run.
- `setup_command` runs once, when the worktree is created.
- `base_branch` is the branch tasks are cut from, and the branch agn compares against when it decides whether a task's work was merged.
- `clean_after_merge: true` removes a task's worktree once agn sees its branch merged. The branch stays; `agn clean --delete-branch` is still yours to run.

## Handoff notes

`agn handoff <task> --to <profile>` appends a handoff section to `.ag/tasks/<task>.md` - goal, decisions made, files touched, what was tried and failed - and starts the next agent with it as the first prompt. The task you hand off is stopped first: the work has moved, and a folder workspace has room for only one agent anyway. The new task inherits the spec and acceptance of the old one and continues its branch.

`--note <text>` is your text. It lands under Goal, and if it carries its own `### Decisions` or `### What failed` headings those fill their slots. `--note -` reads the note from stdin and `--note-file <path>` from a file, so an outgoing agent's own summary can be passed whole. agn fills in the files the branch touched and how the last agent ended; slots nobody wrote read "none recorded". Native session history stays with the original agent; the note is what travels.
